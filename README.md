# file-agent

현장 Windows PC의 지정 폴더를 감시하다가, 새로 생기거나 바뀐 파일을 **TERESA MQ 백엔드로 보내 S3에 적재**하는 데몬입니다. 보낸 파일은 적재 확인(ack)을 받아야만 기록에 남습니다. 그래서 중간에 연결이 끊기거나 PC가 꺼져도 파일이 누락되지 않습니다.

한 대의 에이전트가 **여러 폴더를 동시에 감시**하고, 폴더마다 **서로 다른 S3로 나눠 보낼 수 있습니다**. 어느 폴더를 어느 S3로 보낼지는 백엔드 캔버스에서 정하므로, 에이전트 설정은 바꿀 필요가 없습니다.

**지원 환경:** 64비트 Windows 10(1607 이상)·11, Windows Server 2016 이상입니다. 32비트 Windows와 Windows 7/8.0에서는 실행되지 않습니다. ARM64는 검증하지 않았습니다.

---

## 파일 구성

| | |
|---|---|
| `agent.py` | 데몬 본체 |
| `agent_ui.py` | 설정·상태·시작/중지를 다루는 컨트롤 UI |
| `config.template.json` | 설정 템플릿. 배포본에 들어가며, `config.json`이 없을 때 이 파일로 만듭니다 |
| `install.bat` / `uninstall.bat` | UI를 쓸 수 없을 때를 위한 설치·제거 스크립트 |
| `build-windows.ps1`, `빌드.bat` | 빌드 |
| `file-agent.zip` | 빌드 결과 — **고객사에 보내는 배포 패키지** |
| `build\releases\` | 지금까지 만든 패키지 보관본 (버전·커밋·해시가 파일 이름에 들어감) |

> `sent.jsonl`은 **전송 기록 원장**입니다. 지우면 이미 S3에 있는 파일까지 다시 보냅니다. 폴더를 옮기거나 교체할 때는 반드시 함께 옮기세요.

## 1. 빌드 (개발 PC)

```
빌드.bat
```

더블클릭하면 2분쯤 걸리고 아래 파일이 만들어집니다. 돌고 있는 데몬은 건드리지 않습니다.

| 산출물 | 설명 |
|---|---|
| `build\release-bin\file-agent.exe` | 데몬. 창 없이 돌고, 실행하면 관리자 권한을 요청합니다 |
| `build\release-bin\file-agent-ui.exe` | 컨트롤 UI. 관리자 권한으로 실행됩니다 |
| `file-agent.zip` | 위 둘 + 템플릿 + 설치 스크립트 + `BUILD-INFO.txt`를 묶은 **배포 패키지** |
| `build\releases\` | 만든 패키지와 manifest·해시 보관본. `build\`를 지울 때 이 폴더는 따로 챙기세요 |

- **커밋하지 않은 변경이 있으면 빌드가 멈춥니다.** 고객사에 보낼 패키지는 커밋에서 만들어야 나중에 재현하고 고칠 수 있기 때문입니다. `빌드.bat`은 이때 "시험 패키지를 만들지" 묻습니다. 시험 패키지에는 `dirty` 표시가 붙으니 보내지 마세요.
- `config.template.json`에 토큰·주소·S3 키·IP 주소가 들어 있거나 키가 중복되면 패키징을 거부합니다.
- exe는 코드 서명이 없습니다. 파일 속성의 "자세히" 탭과 `BUILD-INFO.txt`에 버전·커밋·해시가 들어갑니다.

## 2. 배포 패키지 내용

`file-agent.zip`을 풀면 `file-agent` 폴더 하나가 나옵니다.

```
file-agent\
  file-agent.exe          데몬
  file-agent-ui.exe       컨트롤 UI  ← 현장에서는 이것만 쓰면 됩니다
  config.template.json    설정 템플릿 (UI 를 처음 열 때 config.json 으로 복사됨)
  install.bat             설치 (UI 를 쓸 수 없을 때)
  uninstall.bat           제거 (UI 를 쓸 수 없을 때)
  BUILD-INFO.txt          버전·커밋·exe 해시
```

패키지에는 `config.json`이 없습니다. 그래서 새 버전 파일을 기존 설치 폴더에 덮어써도 **현장 설정이 덮이지 않습니다.**

## 3. 현장 설치 순서

1. **`file-agent` 폴더를 로컬 고정 디스크의 전용 위치에 둡니다.** 권장 위치는 `C:\file-agent`입니다.
   - [자동 실행 켜기] 뒤에는 **폴더를 옮기거나 이름을 바꾸면 안 됩니다.**
   - 네트워크 경로·USB·임시 폴더(zip 안의 exe를 바로 실행한 경우)는 UI가 설치를 막습니다. 바탕화면·다운로드 같은 사용자 폴더는 경고합니다.
   - 설치 폴더 안에 zip을 또 풀지 마세요(폴더 중첩).
   - **감시 폴더는 설치 폴더 밖에 두세요.**

2. **`file-agent-ui.exe`를 실행합니다.** 관리자 권한 창이 뜨면 "예"를 누르세요. 한 번만 뜨고, 이후 버튼마다 다시 묻지 않습니다.

3. **「연결」 탭**

   | 칸 | 넣을 값 |
   |---|---|
   | 백엔드 서버 주소 | TERESA MQ 서버의 IP 또는 호스트명. **이 PC의 IP가 아닙니다.** 주소를 통째로 붙여 넣으면 칸을 옮길 때 주소·포트로 나눠집니다 |
   | 포트 | 그 백엔드가 실제로 쓰는 포트. **배포마다 다르니 관리자에게 확인하세요** |
   | 경로 | 백엔드가 하위 경로에 붙어 있을 때만 (예: `mq`). 보통은 비웁니다 |
   | 토큰 | **[새 토큰 생성]** 을 누릅니다. 기본값이나 빈 값으로는 데몬이 시작하지 않습니다(direct 모드 포함) |

   **실제 접속 주소** 줄이 `ws://…/api/file-agent/ws?token=…` 모양인지 확인한 뒤, **[백엔드 연결 테스트]** → **[저장만]** 을 누릅니다.

4. **캔버스에서 노드를 맞춥니다.**
   - Agent Source 노드의 **Mode가 ws**인지 확인합니다.
   - **Token**을 3번에서 만든 값으로 바꿉니다.
   - **WatchDir**(감시 폴더)를 노드당 한 폴더씩 지정하고 엣지를 활성화합니다.
   - backend 모드에서는 **감시 폴더를 캔버스가 정합니다.** UI 「감시 폴더」 탭은 비워 둬도 됩니다.
   - 한 PC 안에서는 폴더의 마지막 이름이 서로 겹치면 안 됩니다(대소문자만 달라도 겹침으로 봅니다). 드라이브 최상위(`D:\`)는 쓰지 마세요.
   - 감시 폴더는 로컬 디스크 경로를 쓰세요. 데몬은 SYSTEM 계정으로 돌기 때문에 매핑 드라이브(`Z:` 등)를 볼 수 없습니다. UNC 경로는 컴퓨터 계정에 권한이 있어야 합니다.

5. **[PC 켤 때 자동 실행: 켜기]** 를 누릅니다. 다음이 한 번에 처리되고, 결과 창에 각 항목의 결과가 나옵니다.
   - **작업 스케줄러 등록:** SYSTEM·최고 권한으로 등록합니다. **로그인하지 않아도 부팅 30초 뒤 수집을 시작**하고, 로그인할 때와 **데몬이 꺼져 있으면 5분마다** 다시 띄웁니다.
   - **방화벽:** 규칙을 등록하고, 예전 포트의 규칙은 지웁니다.
   - **설치 폴더 잠금:** 결과 창에 `폴더 잠금: 적용됨`이 나와야 합니다(9절 참고).
   - **재기동 확인:** 지금 도는 데몬을 멈췄다가 작업으로 다시 띄우고, 응답할 때까지(최대 90초) 기다립니다.

6. **「상태」 탭에서 확인합니다.**
   - `데몬 실행 중`
   - 실행 방식: `백그라운드 (SYSTEM 작업)`
   - 감시 폴더: 캔버스에서 정한 폴더
   - 받을 노드 없어 보류: `0`
   - 볼 수 없는 감시 폴더: `없음`
   - 원장 보관 건수: 늘어나고 있으면 정상

> 4번보다 5번을 먼저 했더라도, 캔버스에서 엣지를 켜면 그동안 "받을 노드 없음"으로 보류됐던 파일을 에이전트가 다시 보냅니다.

## 4. 일상 운영

UI를 열면 필요한 정보는 대부분 「상태」 탭에 있습니다.

| 표시 | 뜻 |
|---|---|
| 데몬 실행 중 / 중지됨 / 정지됨 | 응답까지 확인한 결과입니다. **중지됨**은 [중지]로 멈춘 상태이고, **정지됨**은 스스로 꺼진 상태입니다(5분 안에 다시 뜹니다) |
| 실행 방식 | **백그라운드(SYSTEM 작업)** 가 정상입니다. **현재 사용자 세션**이면 로그오프할 때 멈춥니다 |
| 데몬 기동 시각 | 데몬이 뜬 시각과 PC 부팅 시각. 재부팅 뒤 "부팅 후 1분" 안팎이면 부팅 자동 실행이 된 것입니다 |
| ack 대기 | **아직 적재 확인을 못 받은 파일 수.** 0이 아니면 전송이 밀리는 중입니다. 백엔드·S3가 복구된 뒤에도 최대 `ack_timeout_seconds`(기본 1시간)까지 줄지 않을 수 있습니다 |
| 받을 노드 없어 보류 | 백엔드에 이 파일을 받을 노드가 없는 상태. 캔버스 노드의 Token·WatchDir·엣지 활성화를 확인하세요 |
| 볼 수 없는 감시 폴더 | SYSTEM이 열 수 없는 경로(매핑 드라이브, 권한 없는 공유 등). 폴더가 보이게 되면 자동으로 감시를 시작합니다 |
| 원장 보관 건수 | 지금까지 적재 확인된 파일 수 |
| PC 켤 때 자동 실행 | `켜짐 — 부팅·로그인 때, 꺼져 있으면 5분마다`가 정상입니다. "옛 등록"이면 [켜기]를 한 번 더 누르세요. "다른 폴더에서 운영 중"이면 6절을 보세요 |

**하단 버튼**

- **바꾼 설정** — [저장만] / [저장하고 다시 시작]. 화면에서 바꾼 값만 파일에 씁니다. 「감시 폴더」의 [데몬에 즉시 적용](direct 모드)을 빼면, **모든 값은 데몬을 다시 시작해야 적용**됩니다.
- **지금 실행 중인 데몬**
  - **시작** — 자동 실행이 켜져 있으면 SYSTEM 작업으로 띄웁니다(백그라운드). 꺼져 있으면 현재 사용자 세션에서 띄웁니다(로그오프하면 멈춤).
  - **중지** — 데몬 프로세스를 확실히 끝냅니다. **[시작]을 누르거나 PC를 '다시 시작'(재부팅)할 때까지** 5분 감시가 되살리지 않습니다. ⚠ 빠른 시작이 켜진 PC는 시작 메뉴 **[종료] 후 전원을 켜도 멈춘 상태로 남습니다.** 점검이 끝나면 반드시 [시작]을 누르세요.
  - **다시 시작** — 중지 후 시작.
  - 저장하지 않은 입력이 있으면 먼저 저장할지 묻습니다. 데몬은 파일에 저장된 값만 읽습니다.
  - 한 PC에 데몬은 하나만 뜹니다.
- **PC 켤 때 자동 실행** — [켜기] / [끄기]. [끄기]는 작업과 방화벽 규칙을 지우고, **지금 도는 데몬도 멈춥니다.**

「로그」 탭에서 최근 기록을 보고, 전체 기록은 [로그 파일 전체 열기]로 엽니다. 기록 수준은 **보통**(연결·설정 변경·경고)이 기본입니다. 문제를 추적할 때만 **전부**로 올리세요.

`config.json`은 UI로만 고치세요. 직접 고쳐야 하면 **UTF-8(BOM 없음)** 으로 저장하세요. 데몬은 BOM이 있어도 읽고, UI는 저장할 때 BOM을 지웁니다.

## 5. 업그레이드

**먼저 확인할 것**
- **옛 버전이 기본 토큰(`change-me-please-long-random-token`)으로 돌고 있었다면**, 새 버전은 그 토큰으로 시작하지 않습니다. 순서를 지키세요.
  1. 새 UI로 토큰을 만들고 저장합니다.
  2. 캔버스 Agent Source 노드의 Token을 같은 값으로 바꾸고 다시 활성화합니다.
  3. 그다음 exe를 교체하고 [켜기]를 누릅니다.

  캔버스를 당장 바꿀 수 없으면 업그레이드를 미루세요.
- **1.2.1 이전 버전을 INFO 로그로 운영한 PC**는 옛 `agent.log`에 토큰이 남아 있습니다. 업그레이드 뒤 새 토큰으로 바꾸고(위 순서), 옛 로그를 밖으로 보낼 때는 `token=` 뒤 값을 가리세요.

**UI가 있는 버전(1.2.1 이상)에서 올릴 때**
1. UI에서 **[중지]** 를 누르고 UI를 닫습니다.
2. `config.json`과 `sent.jsonl`을 설치 폴더 밖에 백업합니다.
3. 새 zip을 **설치 폴더 밖에** 풀고, 풀린 `file-agent\` **안의 파일만** 설치 폴더에 덮어씁니다. 폴더가 잠겨 있으므로 탐색기가 관리자 권한을 요청합니다.
4. 설치 폴더의 `file-agent-ui.exe`를 열고 **[켜기]** 를 누릅니다. 작업 등록과 폴더 잠금이 새 버전 기준으로 갱신되고 데몬이 다시 뜹니다.
5. 버전은 「상태」 탭의 **에이전트 버전**이나 `BUILD-INFO.txt`로 확인합니다(창 제목의 번호는 UI 버전입니다).

**UI가 없는 버전(1.2.0 이하)에서 올릴 때**
1. 새 zip을 설치 폴더 밖에 풉니다.
2. 풀린 폴더의 `uninstall.bat`을 실행해 옛 데몬과 작업을 멈춥니다.
3. `config.json`과 `sent.jsonl`을 설치 폴더 밖에 백업합니다.
4. 풀린 `file-agent\` 안의 파일만 기존 설치 폴더에 복사합니다(중첩 금지).
5. 설치 폴더의 UI로 설정을 확인한 뒤 **[켜기]** 를 누릅니다. 옛 설정은 그대로 읽히고, 화면에서 바꾸지 않은 값은 파일에 쓰지 않습니다.
   옛 설정이 `watch_dir` 한 폴더 방식이면, 「감시 폴더」 목록을 바꿔 저장할 때 S3 경로 방식이 바뀐다는 경고가 나옵니다.

**되돌릴 때:** 백업해 둔 옛 exe를 설치 폴더에 되돌리고 옛 `install.bat`(또는 새 UI의 [켜기])을 실행합니다.

**다른 폴더로 옮길 때**
1. `config.json`과 `sent.jsonl`을 새 폴더로 복사합니다.
2. **새 폴더의 UI에서 [켜기]** 를 누르면 자동 실행이 새 폴더로 옮겨집니다.
3. 옛 폴더는 **탐색기로 파일만 지우세요.** 옛 폴더의 UI에서 [끄기]·[중지]·[완전 제거]를 누르면 새 설치의 자동 실행까지 해제될 수 있습니다. 새 UI는 이 경우를 막지만, 옛 UI는 막지 않습니다.

## 6. 제거

- **「상태」 탭 → [완전 제거…]**
  - 데몬 중지와 작업·방화벽 규칙 해제를 먼저 합니다. 해제에 실패하면 아무것도 지우지 않습니다.
  - UI가 닫힌 뒤 **file-agent가 만든 파일만** 지웁니다(exe, 설정, 원장, 로그). 폴더에 다른 파일이 있으면 폴더는 남깁니다.
  - 지우기 전에 `config.json`과 `sent.jsonl`을 `%LOCALAPPDATA%\file-agent-backup\<시각>\`에 백업합니다. 백업에 실패하면 계속할지 묻습니다.
  - 감시 폴더가 설치 폴더 안에 있으면 제거를 중단합니다.
  - **자동 실행이 다른 폴더에 등록돼 있으면** 해제하지 않고, 이 폴더의 데몬과 파일만 정리합니다.
- UI를 쓸 수 없으면 `uninstall.bat`을 실행한 뒤 폴더를 직접 지웁니다.

## 7. 동작 모드

**백엔드 경유 (기본, 권장)** — 파일을 백엔드로 보내고 **백엔드가 S3에 적재**합니다. 어느 S3로 보낼지는 캔버스에서 정하므로, 여러 S3로 나눠 보낼 수 있습니다. 에이전트는 S3 주소도 자격증명도 모릅니다.

**직접 업로드** — 백엔드를 거치지 않고 데몬이 S3에 바로 올립니다. 「S3 (direct)」 탭의 값 하나만 쓰므로 **보낼 곳이 한 군데뿐**이고, 캔버스·모니터링도 쓸 수 없습니다. 백엔드를 둘 수 없는 현장에서만 쓰세요. 이 모드에서도 토큰은 필요합니다(이 PC 안에서 데몬 제어를 막는 용도). 업로드에 실패한 파일은 다음 보정 스캔 때 다시 올립니다.

직접 업로드 값을 넣고 [S3 연결 테스트]를 누르면 접속·인증·버킷·쓰기를 한 번에 확인합니다. 주소가 S3가 아니라 웹 페이지인 경우도 걸러냅니다.

### 여러 PC를 한 백엔드에 붙일 때

한 백엔드에 여러 PC의 에이전트가 동시에 붙어 병렬로 보낼 수 있습니다. 백엔드는 연결과 라우팅을 토큰으로 나눕니다. 다음을 지키세요.

- **PC마다 토큰을 다르게** 둡니다(1 PC = 1 토큰). 같은 토큰을 여러 PC가 쓰면 폴더 목록이 섞이고 저장 위치가 충돌합니다.
- **PC마다 Agent Source 노드를 따로** 만들고, 노드의 Token을 그 PC의 토큰과 같게 합니다. 노드의 Address·Port도 그 PC 값으로 바꿉니다.
- **PC마다 저장 위치를 나눕니다**(버킷을 다르게 하거나 PathPrefix에 `pc-a/`처럼 PC 이름을 넣기). S3 경로에는 PC 정보가 들어가지 않아, 같은 위치를 쓰면 한쪽 파일이 "이미 있음"으로 건너뛰어집니다.
- **백엔드는 단일 인스턴스**로 둡니다(클러스터 기본값은 꺼짐).
- PC가 많으면 PC당 `ws_senders`(기본 48)를 8~16으로 낮춰 백엔드 메모리를 아낍니다.

## 8. 삭제·덮어쓰기 동기화

동기화 모드는 **에이전트(UI 「동기화」 탭)** 와 **캔버스 S3 Bucket 노드(SyncMode)** 두 곳에 있고, 역할이 다릅니다. 백엔드는 노드의 모드를 에이전트에 알려 주지 않으므로 **두 곳을 각각 맞춰야** 합니다.

| 하고 싶은 것 | 에이전트 | 캔버스 노드 |
|---|---|---|
| 새 파일만 올리기 (이미지처럼 안 바뀌는 파일) | 적재만 | speed |
| 덮어쓴 내용까지 S3에 반영 | 상관없음 | **mirror** |
| 로컬에서 지운 파일을 S3에서도 삭제 | **삭제도 알림** | **mirror** |

- **삭제**는 에이전트와 노드를 둘 다 켜야 일어납니다. 에이전트만 켜면 백엔드가 무시하고, 노드만 켜면 에이전트가 삭제를 알리지 않습니다. **지운 파일은 복구되지 않습니다.**
- 에이전트는 **디스크에서 실제로 사라진 파일만** 삭제로 알립니다. 엣지를 끄거나 폴더 구성이 바뀌어 감시 범위에서 빠진 파일은 알리지 않습니다.
- **덮어쓰기**는 노드 설정만으로 정해집니다. 에이전트는 모드와 상관없이 바뀐 파일을 다시 보냅니다.
- ⚠ 노드가 **speed**면 덮어쓴 파일을 "이미 올린 파일"로 보고 건너뜁니다. 오류 없이 완료로 기록되기 때문에 **S3에는 처음 내용이 조용히 남습니다.** 나중에 노드를 mirror로 바꿔도 이미 건너뛴 파일은 저절로 고쳐지지 않습니다. 그 파일을 한 번 더 저장해 수정 시각을 바꿔 주세요.

삭제·덮어쓰기는 S3 Bucket 노드의 **PathPrefix** 안에서만 일어납니다. 다른 자료가 함께 들어 있는 버킷이면 **PathPrefix를 반드시 지정하세요.** 비워 두면 버킷 전체가 대상이 됩니다.

## 9. 보안 메모

데몬은 SYSTEM 권한으로 돕니다. 그래서 다음을 지킵니다.

- **토큰**
  - 비었거나 배포 기본값이면 데몬이 시작하지 않습니다.
  - 토큰은 로그에 남기지 않습니다(`token=***`).
- **원격 접근:** backend·direct 모드에서는 다른 PC에서 오는 요청에 상태 조회(`/health`)만 엽니다. 파일 읽기·감시 폴더 변경은 이 PC 안(127.0.0.1)에서만 됩니다. 옛 PULL 방식 노드는 예외입니다.
- **설치 폴더 잠금**([켜기] 때 적용)
  - SYSTEM·Administrators만 폴더와 파일을 고칠 수 있습니다.
  - 일반 사용자는 폴더를 열어 보고 exe·bat·템플릿·BUILD-INFO를 읽고 실행하는 것만 됩니다. 설정·원장·로그는 읽을 수 없습니다.
  - 압축을 푼 사용자가 파일 소유자로 남아 권한을 바꾸지 못하도록, 소유자를 Administrators로 바꾸고 소유자 권한도 읽기/실행으로 제한합니다.
  - 설치 폴더 안에 하위 폴더가 있으면 그 폴더의 현재 권한은 그대로 고정해 두고(거기에 쓰는 프로그램이 계속 쓸 수 있게) 나머지를 잠급니다.
  - 결과 창에 `폴더 잠금: 안 됨`이 나오면 NTFS 로컬 디스크인지 확인하세요.
- **코드 서명:** exe에 서명이 없어 SmartScreen이나 백신이 막을 수 있습니다.
  - 고객 IT에 `BUILD-INFO.txt`의 SHA256 값으로 예외 등록을 요청하세요.
  - SmartScreen 창이 뜨면 "추가 정보 → 실행"을 누릅니다.
  - '서명된 스크립트만 허용' 정책이 걸린 PC에서는 UI 버튼이 실패할 수 있습니다. 이때는 `install.bat`·`uninstall.bat`을 관리자 권한으로 쓰세요.

## 10. 문제가 생기면

| 증상 | 확인할 것 |
|---|---|
| 백엔드 연결 테스트가 실패 | 「연결」 탭의 주소·포트·토큰. 캔버스 노드의 Token과 같은 값인지 |
| 캔버스 통신 확인은 **실패**인데 파일은 **올라감** | 백엔드가 2026-09-15 이전 버전입니다. 그 버전은 "서버 → 에이전트 PC" 역방향 접속으로 판정하는데, 다른 사이트(공유기 뒤)의 에이전트에는 이 접속이 원래 안 됩니다. **고장이 아니니 무시해도 됩니다.** 연결 여부는 「상태」 탭으로 판단하세요 |
| 로그에 `시작하지 않습니다 — 토큰이…` | [새 토큰 생성] → [저장만] → [시작]. 캔버스 노드 Token도 같은 값으로 |
| 로그에 `시작하지 않습니다 — 포트 … 를 열 수 없습니다` | 다른 프로그램이 그 포트를 씁니다. 「연결」 탭 ②의 포트를 바꾸고 저장 → [켜기] |
| 로그에 `설정 로드 실패` | `config.json` 형식 오류. UI를 열면 `.bak`이나 템플릿으로 되돌릴지 묻습니다 |
| 「상태」에 **받을 노드 없어 보류**가 계속 늘어남 | 캔버스 노드의 Mode(ws)·Token·WatchDir(폴더 이름)·엣지 활성화 |
| 「상태」에 **볼 수 없는 감시 폴더**가 있음 | 매핑 드라이브(`Z:`)를 로컬 경로나 UNC로 바꾸고, UNC면 컴퓨터 계정 권한을 확인 |
| 로그에 `SSL: WRONG_VERSION_NUMBER` | 「연결」 탭의 **HTTPS 체크를 해제**하세요. 백엔드 포트에 바로 붙을 때는 암호화를 쓰지 않습니다 |
| 로그에 `HTTP Error 400` / 접속 주소가 이상함 | 「경로(선택)」 칸을 비우세요. 이 칸에는 주소를 넣지 않습니다 |
| [시작] 뒤 "응답하지 않습니다" | 첫 기동은 백신 검사·큰 원장 때문에 1~2분 걸릴 수 있습니다. 잠시 뒤 「상태」를 다시 보고, 계속되면 「로그」 탭을 확인하세요 |
| 재부팅 후 수집이 안 됨 | 「PC 켤 때 자동 실행」이 켜져 있는지, [중지] 상태가 아닌지(빠른 시작 PC는 [종료]로 풀리지 않음), 실행 방식이 백그라운드인지 |
| 상태가 **정지됨**으로 반복 | 「로그」 탭의 ERROR 줄. 데몬이 시작하자마자 끝나는 중입니다(5분마다 재시도) |
| [켜기] 결과에 `폴더 잠금: 안 됨` | NTFS 로컬 디스크인지, 설치 폴더를 다른 프로그램이 잡고 있지 않은지 |
| 「PC 켤 때 자동 실행」에 "다른 폴더에서 운영 중" | 이 폴더는 옛 설치입니다. 버튼을 쓰지 말고 파일만 지우거나, 이 폴더로 옮기려면 [켜기] |
| 파일이 안 올라감 | 「상태」 탭의 **ack 대기** 수. 계속 쌓이면 백엔드나 S3 쪽 문제입니다 |
| 디스크가 찬다 | 「상태」 탭 아래 **임시 폴더 정리** |

로그만으로 원인을 찾지 못하면 「로그」 탭의 **[지원용 파일 만들기]** 를 누르고, 바탕화면에 생긴 zip을 보내 주세요. 로그·설정·빌드 정보·상태가 들어 있고, 토큰과 S3 키는 가려집니다. 설치 폴더는 잠겨 있으니 탐색기에서 권한 요청에 '계속'을 눌러 열지 마세요. 누르면 그 계정에 권한이 영구히 추가돼 잠금이 약해집니다.
